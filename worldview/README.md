# Мапа бачення

Особиста мапа рішень: позиції, які ти займаєш знову й знову, записані так, щоб їх прочитала і людина через пів року, і модель посеред задачі. Потім мапа йде агентові як рушій: грати в ігри, писати програми, працювати разом.

Зроблено за специфікацією «Мапа рішень». Три речі з неї тримають усю конструкцію:

- **Головне — файл.** Мапа — це `.md`, який читає людина. JSON для програм виводиться з нього. Рядки, яких парсер не розуміє, лишаються на своїх місцях: правка торкається лише свого рядка.
- **Кнопка ≠ рядок.** Кнопка живе поруч із питанням. У мапу лягає рядок, що читається без питання.
- **Агентові — не всю мапу.** Тільки теми, яких торкається задача, з підписом: звідки це, яка в нього влада і що його б’є.

## Запуск

Потрібен лише Node 18+. Залежностей нема.

```sh
cd worldview
node server.js                 # http://localhost:4321
node server.js --host 0.0.0.0  # щоб відкрити з телефона в тій самій мережі
node server.js --map ../my-map # тримати мапу деінде, наприклад у приватному репо
```

Сервер пише `map/<сфера>.md` на кожен тап і поруч `map/<сфера>.json`. Файли можна правити руками: сторінка підхопить правку, щойно повернешся до неї. Тека `map/` не в `.gitignore` навмисно, бо одна копія — це жодної копії. Якщо репозиторій публічний, винеси мапу через `--map`.

Та сама сторінка працює і як артефакт на claude.ai. Там мапа лежить у сховищі сторінки, окремо для кожного, хто її відкрив. Без сервера й без claude.ai вона житиме лише в браузері; сторінка про це попереджає.

## Що на екрані

- **Питання.** Картки йдуть упереміш: сфери й теми чергуються, щоб мапа заповнювалась рівно. «Легенда» показує поступ по темах, без загального відсотка; тап по темі — питати спершу з неї. «Бліц»: десять коротких питань, вісім секунд на кожне, а наприкінці все, що лягло за раунд, з можливістю стерти.
- **Відповіді.** Мапа так, як вона лежить у файлі: розділи, рядки, службові поля. Можна стерти рядок, і питання повернеться. Позначки «не знаю» показують, чи питання вже переписали. Тут же — блок для агента й експорт `.md` + `.json`.
- **Файл.** Сирий `.md`: подивитись, поправити руками, вставити свій старий файл.

«Не знаю» і «Пізніше» — різні речі. «Пізніше» означає «не зараз», і питання повернеться таким самим. «Не знаю» означає, що питання не влучило: це звіт автору банку, і питання повернеться, коли його перепишуть.

## Формати питань

Усі формати закінчуються однаково: одним рядком у мапі.

| kind | що робиш | що лягає в мапу |
|---|---|---|
| `choice` | тиснеш одну з 2–4 кнопок | `line` вибраного варіанта |
| `duel` | обираєш один із двох зразків: код, відповідь, сцену | `line` зразка |
| `scale` | ставиш позначку між двома полюсами | `line` позначки |
| `rank` | розставляєш 3–5 пунктів за важливістю | шаблон `line` з `{1}`, `{2}`… |
| `taboo` | позначаєш, чого не буде ніколи | шаблон `line` з `{list}`, або `none` |
| `open` | пишеш своїми словами | шаблон `line` з `{text}`, у дужках позначка `своє` |
| `feel` | пробуєш два варіанти міні-гри наосліп | `line` того, що сподобалось |

`feel` міряє не те, що кажеш, а те, що обираєш рукою: підписи «А» і «Б» нічого не видають, а рядок каже, що це було насправді. Демо лежать в `app/demos.js`: `move` (керування з інерцією чи без) і `hit` (влучання: хітбокс, темп). Нове питання на їхній основі не потребує коду — лише інших `params`.

## Банк питань

`bank/index.json` перелічує сфери, `bank/<сфера>.json` — теми й питання. Приклад найпростішого:

```json
{
  "id": "forgiving_hits",
  "topic": "controls",
  "text": "Гравець промахнувся на волосину. Що робить гра?",
  "options": [
    { "label": "прощає промах", "line": "гра прощає дрібний промах: влучання трохи щедріше, ніж виглядає" },
    { "label": "що видно, те й є", "line": "гра не прощає промаху: влучання рівно таке, як виглядає" }
  ]
}
```

- `id` — ASCII, нижній регістр, `_`. Під ним лежить відповідь: перейменуєш — осиротиш. Те саме питання, поставлене краще, лишає `id`, і тоді воно повертається до тих, хто сказав «не знаю».
- `label` — до 36 символів. `line` мусить стояти сам і казати більше за кнопку.
- Необов’язкові поля: `setup` (сцена перед питанням) і `author`.
- Масив питань у форматі специфікації теж приймається як банк.

Порушення правил §3 не ламають сторінку. Вони з’являються внизу «Відповідей» як зауваги до банку: задовга кнопка, рядок, що повторює кнопку, «як часто» (число, перевдягнене в напрям).

**Про стартовий банк.** Специфікація каже, що питання пише людина, а не модель, бо модель питає про те, що сама вважає важливим. Стартові питання в `games`, `code` і `agent` написав Claude, щоб було з чим грати від першого дня. Кожне з них має `"author": "claude"`, і картка це показує. Заміни їх своїми, а ті, що не влучили, познач «не знаю». Питання `forgiving_hits` взяте зі специфікації дослівно.

## Для агента

```sh
node context.js games                      # які теми є
node context.js games controls failure     # блок для задачі
node context.js code errors --file ~/Downloads/code.md
```

Виходить блок з підписом і рядками вибраних тем, без службових полів. Той самий блок збирає вкладка «Відповіді» (кнопка «Скопіювати»). Клади його в саму задачу, а не в системний промпт чи CLAUDE.md: їх кешують, і особиста вставка там скидає кеш. Старшинство: задача → проєкт → мапа.

## Як усе влаштовано

```
core/            чисте ядро: без DOM і без I/O; його ж імпортують server.js і context.js
  mapfile.js     формат .md: читання, правки рядок у рядок, undo
  bank.js        банк питань і лінтер правил §3
  kinds.js       формати питань → один рядок
  queue.js       що питати далі; легенда
  export.js      JSON і блок для агента
app/             сторінка
  stores.js      порт Store: сховище claude.ai | файли через server.js | браузер
  controller.js  стан і всі зміни
  cards.js       картка на кожен формат
  demos.js       міні-ігри для feel
  render.js      три вкладки
bank/            банк питань, правиться руками
map/             мапа (створює server.js)
```

Кожна зміна — це `Op` (`answer`, `unanswer`, `mark`, `unmark`, `replace`). Вона одразу застосовується до екрана, а тоді записується поверх свіжого читання сховища. Тож ні ручна правка файлу, ні інший пристрій не перезаписуються. Сховище знає лише «текст за назвою сфери», тому новий бекенд — це три функції.

`index.html` написаний без `<!doctype>` і `<head>`: так його публікує claude.ai. Локально ту саму обгортку додає `server.js`.

## Тести

```sh
npm test
```

Серед них: розбір прикладу `.md` зі специфікації дослівно, збереження рядків, яких парсер не розуміє, undo для кожного типу змін, лінтер банку і перевірка, що стартовий банк проходить власні правила.
